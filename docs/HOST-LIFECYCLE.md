# Host 程序管理

同一個使用者帳號下，相同裝置 ID 的 Host 共用作業系統檔案鎖，與執行檔所在目錄、APP 版本無關。後啟動的 Host 先等待鎖釋放，再進行配對；不刪除鎖檔，避免執行中繞過鎖。程序結束時由作業系統釋放鎖。

管理 APP 透過私有標準輸入管線傳入密碼，並以 `-parent-stdin` 明確啟用生命週期監測。APP 異常結束時管線關閉，Host 取消擷取與連線；驅動若無法退出，五秒後強制結束自身。一般手動使用 `-secret-stdin` 不受影響。

Server 回報同 ID 的 Host 已占用時，APP 顯示「此裝置已有另一個 Host 連線，請結束原程式後再試。」此狀態不會要求更改連線密碼。

## 適用範圍

- APP 已有單一實例鎖，本次補上獨立 Host 鎖與父程序生命週期。
- 舊版 Host 沒有新鎖與監測機制；首次更新時需從 Tray 結束舊 APP。若曾異常退出，應在工作管理員確認舊 Host 已退出。
- 不會終止未知程序、不會搶占 Server 上仍有效的其他 Host。
- 不同系統帳號仍由 Server 的同 ID 排他規則處理。
- 本次完成編譯檢查；Windows 實機的強制關閉與重新啟動行為仍需驗證。

Windows 新版 Host 取得鎖後記錄 PID、執行檔路徑與程序建立時間。發現本機鎖被占用且身分核對成功時，APP 顯示停止確認對話框；確認後仍會重新核對，並使用同一個程序 Handle 執行停止。舊版或僅由 Server 回報的占用若無法確認本機程序，保留警告，不猜測 PID。

## Windows 啟動前檢查

管理 APP 在啟動 Host 前，使用 Windows CIM 查詢既有 `yourdesk-client.exe`。排除自身及已管理的子程序，核對相同 Windows 帳號、裝置 ID、配對服務位址，並排除介面與單次查詢模式。啟動參數只在記憶體比對，不提供給介面或寫入 LOG。

找到符合條件的程序時，先顯示 PID 與完整路徑，等使用者確認停止，或自行結束該程序，再重新檢查並啟動 Host。取消對話框不會停止程序，也不會啟動新的 Host 搶占。若無法取得足夠資訊，保留原本的衝突警告機制。

停止前核對 PID、路徑及建立時間，且由同一個 Windows Handle 核對與停止，避免 PID 重用。建立時間以字串傳給介面，避免 JavaScript 數值精度造成比對失敗。

本次僅完成 macOS、Windows x64／ARM64 編譯檢查，Windows 實機行為仍待確認。Server 遠端停止指令暫不實作，待另行評估授權與防冒用設計。
