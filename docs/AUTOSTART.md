# 登入前啟動

進階設定的「登入前啟動」直接管理系統層級的登入前連線服務，預設關閉。網路安全頁原有的「未登入開機」已整併至此，開啟時不再要求先建立使用者登入後的啟動項目。

## 行為與支援範圍

macOS 14.4 以上的已簽署 `YourDesk.app` 可透過管理員授權安裝 LaunchDaemon 與 Aqua／LoginWindow 代理，讓 Host 在作業系統登入前啟動，登入後亦由服務管理。啟用時沿用當前裝置 ID、配對伺服器、連線密碼及 Host 設定，並交接目前 Host；現有被控連線可能中斷。關閉時經管理員授權移除服務，再由 APP 恢復一般 Host。

Windows 使用 SCM 的 `YourDeskPrelogin` 自動啟動服務，以 LocalSystem 執行，開機後不需登入即啟動桌面代理；同一服務在登入後持續管理 Host。啟用與停用透過 UAC 要求管理員授權，服務有獨立受保護副本，未依賴 HKCU Run。更新或解除安裝前須先關閉此開關。

此功能仍為實驗實作。macOS 必須先允許螢幕錄製及輔助使用，不支援 FileVault 開機解鎖畫面。Windows 不支援 BitLocker 開機前解鎖；使用者已確認服務啟動、初步實機測試可用，長時間穩定性及登入、鎖定、桌面輸入的完整情境仍待觀察。Linux 尚未實作登入前服務，介面停用此開關並顯示原因。詳細機制及限制見 [登入前服務文件](PRELOGIN-IMPLEMENTATION.md)。

介面使用 `GET /api/prelogin` 查詢、`POST /api/prelogin` 設定，內容為 `{"enabled": true}` 或 `{"enabled": false}`。設定回傳 HTTP 202 後輪詢服務狀態，顯示管理員授權進度及錯誤。舊的 `GET /api/autostart`、`PUT /api/autostart` 共用相同服務流程；PUT 同樣為非同步操作。狀態以系統服務為準，不隨站台設定匯入／匯出。

## 既有登入後啟動相容性

CLI 的 `-autostart on|off|status` 保留原有使用者登入後啟動語意，與進階設定的登入前服務獨立。既有使用者啟動項目不會自動升級成需要管理員權限的系統服務；如需移除，使用原本啟用時的 CLI 模式執行 `-autostart off`（桌面項目加 `-ui`）。停用此舊項目不再要求先停用登入前服務。

## 驗證範圍

編譯及語法檢查不代表實機登入前擷取或輸入已驗證。此次未安裝系統服務、登出或重新啟動電腦。
