# 網路 Debug 與雙向封包測試

## build 2323 驗證狀態

目前回報的停滯／斷線問題只發生在 macOS 對 macOS；其他平台尚未觀察到相同問題。升級整組 Pion 傳輸套件後，使用者回報單一連線及同時連線兩個遠端均維持穩定，較先前測試版本改善。這是目前測試環境的觀察，**尚未完全確認原先 Mac 對 Mac 停滯／斷線問題已解決**，也未確認具體根因；長時間與大檔案傳輸仍需驗證。本版未加入背景自動重連或斷線續傳，穩定性觀察不是由自動重連掩蓋中斷所得。

在「設定 → 關於 → 強制更新」下方開啟「網路 Debug」。預設關閉；開啟後，站台編號左側、原有測速圖示之前顯示雙向箭頭測試按鈕。

兩台電腦都需更新並各自開啟開關。點站台測試圖示僅開啟視窗；由使用者按「開始測試」後才自動建立獨立背景連線、隱藏視窗並暫停串流，再開始測試；未儲存密碼時直接在測試視窗輸入。不支援的舊版會顯示更新提示，不會改動既有連線協議。

測試沿用目前已授權 WebRTC 的可靠控制通道，最多四個在途請求持續交換 256、1,200、4,096 bytes 隨機資料，分別校驗上行與下行 SHA-256，總長約 60 秒。畫面呈現已確認收送量、成功往返數與平均往返延遲。應用層資料經 SCTP 分片，不等於單一 UDP datagram；此測試不是獨立 UDP 對打、不是最大頻寬測試，也不把請求逾時解釋為 UDP 丟包率。

每批最多送出兩秒，最多四個未完成請求；回覆逾時時休息一秒重試，最多保留 30 秒測試恢復時間；不支援或校驗錯誤立即停止。關閉測試視窗停止下一批，已在途請求最遲約五秒結束，會清理測試專用連線，不會關閉使用者原有桌面連線。背景連線最長兩分半鐘後自動回收，避免介面意外關閉而殘留。關閉 Debug 亦停止下一批並停止新增診斷日誌；保留既有日誌。

## 分層編號

| 編號 | 觀測點 | 紀錄 |
|---|---|---|
| L1 | 應用層測試 | 每批嘗試／往返驗證數、雙向校驗成功量、耗時與錯誤 |
| L2 | DataChannel | 各通道訊息數、收送 bytes、狀態與待送量 |
| L3 | SCTP | 收送 bytes、壅塞視窗、接收視窗、RTT |
| L4 | DTLS | 連線狀態；目前套件 API 不提供此處獨立封包計數 |
| L5 | ICE 傳輸 | Pion 傳輸收送 bytes；送出計數不保證 socket 已送出 |
| L6 | UDP socket | ReadFrom／WriteTo 回傳量、封包數、最大 payload、錯誤與邊界計數 |

送出方向 L1 → L6，接收方向 L6 → L1。這些是固定觀測層級，不是封包一對一編號；可靠傳輸會分片、合併、重傳，不能直接拿不同層的訊息數相減當丟包率。L4 狀態維持 connected 也不能證明仍有資料進展。L6 目前觀測原生 Pion UDP 路徑，不涵蓋 Tailcat 虛擬傳輸。

日誌依作業系統使用者 cache 路徑保存；macOS 為 `~/Library/Caches/YourDesk/Logs`。同帳號 Host、Viewer 與 UI 共用持久化 Debug 開關，不需重啟連線。未開啟時不建立 JSONL；每次寫入前核對開關。每程序檔案上限 5 MiB，新開日誌清理超過七天的 JSONL；不記錄測試資料內容、密碼、金鑰或 SDP。關閉並不刪除歷史紀錄。

應比對同時段兩端最後仍持續增加的層級，定位異常範圍；最後有進展的編號不等於該層就是故障根因。

## 畫面上的層級進度

每 500 毫秒取樣本機各層計數，每批回傳至畫面。只有實際觀察到收送增量的層級才顯示，DTLS 例外僅顯示已確認的連線狀態。曾到達的層級會保留，分別顯示本批送出／接收增量與距離最後進展的時間。未曾觀察到的方向標示「尚未觀察到進展」，不臆測故障位置。這是本機觀測表，L1 成功往返另有對端內容校驗；不是完整遠端分層表。

## 壅塞與存活判斷

心跳逾時並不直接判定失效。只要仍收到 DataChannel 應用資料，就延後失效判斷；僅本機送出增加不算對端仍有進展。心跳持續失敗且至少 30 秒完全沒有接收進展，才清理失效連線。心跳回覆成功重設狀態。兩端均應更新，否則舊端仍可能依舊規則先關閉連線。

## Pion 套件升級對照

本次改用 WebRTC 4.2.20、SCTP 1.11.1、DataChannel 1.6.2、DTLS 3.1.8、ICE 4.4.2，UDP 診斷包裝同步移轉 transport/v4 4.1.0。依賴由 WebRTC 的 go.mod 統一解析，不混用 transport/v3 的型別。

SCTP 新版包含 [SACK 邊界迴圈修正 #469](https://github.com/pion/sctp/pull/469)。這僅證明升級包含該修正，尚不能證明原先停滯就是該缺陷；需要兩端更新後重做同條件測試。[WebRTC 發布紀錄](https://github.com/pion/webrtc/releases/tag/v4.2.20)、[SCTP 發布紀錄](https://github.com/pion/sctp/releases/tag/v1.11.1)。
