# 系統快捷鍵作用對象

遠端桌面控制啟用時，以下快捷鍵先顯示「本機／遠端／取消」對話框，每次操作各自確認：

| 觀看端 | 快捷鍵 | 選擇本機 |
| --- | --- | --- |
| macOS | Cmd+Q | 結束本機 YourDesk |
| macOS | Cmd+W | 關閉本機遠端顯示視窗 |
| Windows | Ctrl+W、Alt+F4 | 關閉本機遠端顯示視窗 |
| Windows | Ctrl+Shift+Esc | 開啟本機工作管理員 |

選擇遠端時，只向目前連線送出一次完整按下／放開序列，沿用目前 MacOS/Windows 按鍵映射設定。例如 Mac 連 Windows 且映射啟用時，Cmd+W 仍轉為 Ctrl+W。這是鍵盤轉送，實際行為由遠端前景程式決定。

Ctrl/Cmd+C、V 等一般編輯快捷鍵不新增詢問，沿用原有剪貼簿流程。工具列的「系統快捷鍵」選單也可開啟上述選擇，不必按實體快捷鍵。點擊視窗關閉按鈕仍是明確的本機操作。

對話框預設選取遠端，按 Enter 確認遠端操作；Escape 取消。遠端不可用或安全快捷鍵無法執行時，預設選取取消。開啟前釋放遠端已按下的鍵與滑鼠、取消排隊中的輸入。等待期間不轉送鍵鼠，選擇後等待觸發鍵、修飾鍵及確認按鍵／滑鼠放開，再執行一次；不重播等待期間的輸入。遠端斷線時取消對話框，視野或連線變更後不送出原先確認的快捷鍵。

## Ctrl+Alt+Del 的限制

Windows 實體 Ctrl+Alt+Del 由作業系統優先處理，一般程式無法保證攔截後再詢問。現有 Host／登入前服務也沒有安全注意序列的傳送能力，不能使用一般 `SendInput` 代替。

工具列的 Ctrl+Alt+Del 入口，以及 macOS 能捕捉到的 Ctrl+Alt+Delete，會顯示限制說明並停用本機／遠端執行按鈕，不宣稱成功送出。這次未加入 SendSAS 服務或修改 Windows 安全政策；其他由系統先行攔截的組合鍵亦不保證能顯示對話框。

## 驗證

- `go test ./internal/shortcut ./cmd/remote`：快捷鍵分類、一般 C/V 不攔截、修飾鍵順序與成對放開、拒絕合成安全注意序列。
- `scripts/smoke-system-shortcuts.cjs`：使用瀏覽器與模擬原生橋接檢查三種選擇、預設遠端、不可用時預設取消、Escape、焦點圈選、失焦取消、安全序列限制及四語系窄視窗；不會真的結束 APP、開啟工作管理員或操作遠端。
- macOS 原生介面及 Windows x64／ARM64 編譯檢查不取代跨電腦實際按鍵與系統行為驗證。
