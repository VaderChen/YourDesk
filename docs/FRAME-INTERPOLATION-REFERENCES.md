# 補幀破碎問題與參考演算法

研究日期：2026-09-09。依使用者試用回饋，早期補幀原型已有流暢效果，但生成畫面破碎。本文件為程式碼分析與文獻選型，後續已接入 RIFE，以下區塊匹配分析保留為歷史原型紀錄；目前實作見 [補幀管線](FRAME-INTERPOLATION.md)。

## 早期原型問題

早期 `cmd/remote/interpolation.go` 原型使用 16×16 獨立區塊，每塊只取 9 個亮度樣本，搜尋 ±16 像素、步距 4。下列為程式碼可確認的限制；它們與破碎現象相符，但仍需相同影格的前後比較確認各因素的影響。

- 區塊之間沒有位移連續性、重疊融合或物件邊界限制，相鄰區塊容易往不同方向移動。
- 稀疏亮度比對容易把重複文字、欄位、背景認成相同內容；位移只有粗略整數精度。
- 只估 A→B 位移，沒有 B→A 一致性判斷及遮擋遮罩。被視窗遮住或新露出的區域不適合平均兩張圖。
- 將來源位置的位移直接套到中間影格位置，是近似映射；在移動邊界與遮擋處尤其不可靠。
- 低信心區塊直接採用 B，鄰塊卻顯示中間時刻，造成時間與位置接縫。
- 低來源 FPS 的相鄰畫面位移較大，快速捲動容易超出搜尋範圍。提高 Render FPS 不會補回原本沒有擷取的內容。

## 優先參考

| 演算法／論文 | 可借鏡之處 | YourDesk 適用判斷 |
| --- | --- | --- |
| RIFE，ECCV 2022 | 直接估計中間光流，支援時間位置輸入，並完成影格合成 | 優先做品質原型，不需要遠端提供深度或遊戲動作向量 |
| DIS，ECCV 2016 | 多尺度搜尋、重疊區塊彙整成密集位移場、變分精修 | 適合傳統 CPU 光流候選，但仍須另做遮擋判斷及補幀合成 |
| Softmax Splatting，CVPR 2020 | 處理前向投射時多個像素落在相同目標位置的融合衝突 | 參考遮擋與合成設計；不是單純替換搜尋函式即可完成 |

RIFE 的論文目標與本需求接近：從影格本身推算中間畫面，支援任意時間位置，可對應 2× 的 t=1/2，以及未來 3× 的 t=1/3、2/3。[RIFE 論文](https://arxiv.org/abs/2011.06294)

Practical-RIFE 作者提供較低計算量的 lite 模型；目前頁面列有 4.25.lite，並以一般版 4.25 作多數場景的預設建議。建議先拿 4.25.lite 做即時候選，以 4.25 作畫質對照，不把論文中的硬體速度直接當成本機效能。[Practical-RIFE 作者專案](https://github.com/hzwer/Practical-RIFE)

DIS 的重點是先透過影像金字塔處理較大位移，再彙整重疊區塊並精修。它可以改善目前各塊獨立移動的問題，但光流本身不等於完整的補幀器。[DIS 論文](https://arxiv.org/abs/1603.03590)、[作者程式](https://github.com/tikroeger/OF_DIS)

Softmax Splatting 針對前向變形的多對一衝突設計可微分加權合成，值得參考視窗遮擋、物件邊界及新露出背景的處理。[CVPR 論文](https://openaccess.thecvf.com/content_CVPR_2020/html/Niklaus_Softmax_Splatting_for_Video_Frame_Interpolation_CVPR_2020_paper.html)

## 原型階段選型紀錄

優先評估 RIFE lite，保留目前的開關、時間排程、逾時取消與 Render FPS 統計，將生成中間幀的部分替換成可插拔後端。先以同一段錄製桌面做離線比較，再決定部署；不繼續把現有粗略區塊匹配當成正式畫質方案。

macOS 可評估 Core ML，Windows 可評估 ncnn Vulkan；兩者都需要確認具體模型的算子、權重與執行後端相容性。不能假設 RIFE 可直接套用現有 QuickSRNet 的單張 RGB 2× 介面，也不能假設 ncnn 已支援作者提供的每一版 lite 模型。現有 RIFE ncnn 實作可供整合參考。[RIFE ncnn Vulkan](https://github.com/nihui/rife-ncnn-vulkan)

若先走 CPU 方案，完整管線應為：雙向 DIS → 前後向一致性檢查 → 遮擋／信心遮罩 → 次像素變形 → 邊界感知融合。單純把位移平滑或把畫面模糊，可能減少接縫卻增加文字重影。

評估時先在傳輸尺寸生成中間幀，再沿用超解析度放大；Core ML 超解析度的非同步排程也須配合，以免生成幀被丟棄。主要比較文字捲動、視窗拖曳、游標、影片、場景切換，記錄生成耗時、逾時率、實際 Render FPS 與額外操作延遲。桌面文字與游標應保守處理；信心不足時整體回退或連續融合，避免硬切出新的時間接縫。

後續離線實驗比較 DIS、RIFE 與視窗邊界輔助校正；提高來源取樣率由 12 至 20 FPS 可降低該測試的邊界誤差，但尚未找到通用臨界值。新版 FSR SDK 未直接接入或在 Mac 執行；視窗追蹤校正也尚未納入正式管線。
