# Agent 按需畫面與座標

MCP 桌面連線支援持續串流與按需截圖。兩端須更新至包含 `video.stream`、`video.snapshot` 指令的版本；舊 Host 維持全螢幕串流及原有座標，要求區域或暫停會明確回報不支援，不會把隱藏視窗視為已暫停串流。

## 使用方式

- `connect` 可指定 `videoMode: "paused"`，完成連線與功能協商後立即暫停；省略則維持串流。若舊 Host 未提供此能力，連線保留並退回全螢幕串流，APP 顯示相容性提示。協商完成前可能有少量在途影格，Viewer 不會顯示這些影格。
- `set_video_mode`：`mode: "paused"` 停止持續擷取、編碼與傳送影格，保留 P2P、控制、剪貼簿及恢復串流的能力；`mode: "streaming"` 恢復並要求完整影格。
- `snapshot`：重新向遠端 OS 擷取一張 PNG，不讀取串流快取，也不會自行恢復已暫停的串流。最大邊長 1280 像素。舊 Host 的全螢幕請求會改用最近收到的影格，回覆標記 `legacy: true`、`fresh: false`，不冒稱即時按需擷取；區域或暫停請求不會靜默降級。
- `remote_action` 的 `screenshot` 在新版 Host 也使用按需擷取；舊 Host 保留原有收到影格的截圖功能。

`set_video_mode` 與 `snapshot` 接受 `session`、可選的 `mode`、`region`、`fullScreen`。範圍設定由兩者共用：省略保留目前視野，`fullScreen: true` 恢復完整螢幕；不能同時指定 `region`。

例如，暫停串流並擷取目前螢幕中央四分之一面積：

```json
{"session":"viewer:站台ID","mode":"paused","region":{"x":0.25,"y":0.25,"width":0.5,"height":0.5}}
```

可將上述參數直接交給 `snapshot`，一次完成範圍選擇、暫停及新截圖。需要串流時呼叫 `set_video_mode`，提供 `mode: "streaming"`，其餘範圍不變。

## 滑鼠座標

`region` 的四個數值相對於所選的**完整螢幕**，範圍為 0～1。`remote_action` 的 `move`、`button` 則相對於**回傳圖片**：左上角 `(0,0)`、右下角 `(1,1)`，圖片中心 `(0.5,0.5)`。

Agent 不應再次加上區域偏移。Host 使用同一個矩形分別計算影像像素裁切與桌面邏輯座標，再由既有輸入層換算位置，包含 Retina 縮放及位於主螢幕左方／上方的負座標。截圖縮小不改變相對座標。

切換螢幕或視野後，先取得新截圖再輸入。視野切換會釋放已按下的鍵與滑鼠按鈕，清除補幀狀態；影格及滑鼠輸入攜帶視野版本，過期版本不予顯示／執行。命令逾時而未確認範圍時，Viewer 暫停接受座標輸入，直到重新設定或截圖成功。

## 傳輸與相容性

截圖透過現有可靠 P2P 指令通道分塊讀取，每塊 8192 位元組、最多三個平行讀取，總量上限 8 MiB。快取只存在該連線記憶體，讀取完成關閉；35 秒後不可讀取，下一次讀取或操作會釋放過期內容，連線結束也會釋放。

只有對端主動使用新視野指令，Host 才啟用含 8 位元組視野版本的影格標頭。一般舊版連線維持原有標頭。暫停確認後不再排入影格；已在途影格由 Viewer 依版本丟棄。

本功能不需要變更 Signaling Server，可沿用既有協議。
