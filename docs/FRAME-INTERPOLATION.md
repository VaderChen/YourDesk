# 補幀試用版

設定 → 畫面增強 → 2× 補幀（實驗性），預設關閉。補幀本身只需更新 遠端顯示；本版可調整 GOP 則需要兩端更新，詳見 [串流設定](STREAMING-CONTROLS.md)。補幀獨立於超解析度開關；舊設定缺少 interpolation 時視為關閉。

補幀方式可選「自動（Apple 優先）」、「Apple 低延遲」與「RIFE 4.25 Lite」。自動模式在支援的 Mac 優先使用 Apple，其他裝置選擇 RIFE。明確選擇 Apple 而裝置不支援時，顯示不可用原因並呈現真實影格。舊設定缺少 `interpolationMethod` 時視為自動；補幀開關本身仍預設關閉。

Apple 低延遲補幀限定 macOS 27 以上的支援機型；系統版本、硬體支援、最大邊長與像素數能力均通過才啟用。API 本身自 macOS 26 提供，本產品不在 macOS 26 啟用；僅進行時間插值，不開啟其 2× 空間放大。Apple 模式的真實幀與生成幀共用固定工作尺寸，限制於 1280 最長邊及 720p 像素預算；較大影格先等比例縮小並對齊偶數，再統一縮放至顯示區域。等待、逾時或場景跳變時也使用相同尺寸的真實幀回退，避免高解析真實幀與低解析生成幀交替造成清晰度閃爍。同一來源尺寸下保持工作尺寸不變，切換螢幕或來源尺寸才重建。代價是 Apple 模式的真實幀也會降低解析度；關閉補幀或切換 RIFE 後恢復各自的呈現路徑。這是即時處理預算，不代表裝置的 API 硬上限；工作尺寸取系統能力與預算的交集，能力回報零或尺寸無效時不建立處理 session。背景工作重用處理 session 與影像緩衝，工作尺寸變更才重建；初始化及處理超過原有時間預算時丟棄結果，繼續顯示真實影格。切換方式會清除補幀歷史。這是接收端功能，遠端不需因本次補幀方式更新。

RIFE 4.25 Lite Core ML 支援 Apple Silicon、macOS 13 以上。Windows 暫時停用補幀，顯示真實影格，避免回退到原本會產生破碎的區塊匹配。Windows 的 ncnn 後端尚未完成。

## 共用排程與 RIFE 管線

選用 RIFE 時才在背景載入並暖機。將兩張畫面等比縮小、邊緣補齊至 512×384，預測 t=0.5 的雙向中間光流及遮擋遮罩。回到原始解析度，以連續光流雙線性取樣兩張原圖、遮罩融合，CPU 平行處理各列；不再使用獨立 16×16 區塊硬切接縫。Core ML 使用 CPU／GPU，自動選擇內部排程，不宣稱 ANE。

新影格到達後先暫存，補出中點，再顯示真實幀。接收間距在 20～150 ms 才嘗試；工作預算為一個來源週期與 50 ms 的較小值，中間幀顯示時間另以半週期計算。先處理既有補幀結果再接收新工作，避免開 FSR 後因繪製排程延遲而取消已完成結果；僅保留一張最新待處理快照，不累積佇列。過期結果丟棄；Core ML 單次推論無法由 context 強制中斷，逾時後會等其返回再釋放工作槽。切換螢幕、尺寸、開關、場景跳變會清除或放棄歷史。

補幀可能增加操作延遲。啟用時工具列以亮綠色顯示 Render FPS（包含生成幀，不計同幀重畫），關閉恢復來源 FPS。2× 是模式目標，不代表所有裝置都能達成。

## 拖動期間的流暢度

補幀啟用後，滑鼠移動、按住拖曳、滾輪與鍵盤操作均持續執行所選補幀方式；不再因操作停用補幀，也不再在放開後等待 250 ms 重啟。Core ML 超解析度不因鍵鼠操作切換為 FSR，避免反覆重設影格歷史。

Render FPS 維持實際計數，不乘以固定倍率或平滑成虛假數字。模型不可用、計算逾時、來源間隔異常、場景跳變及尺寸／螢幕切換仍會回退，因此不保證恆定 FPS。取捨是拖動期間也可能看見 RIFE 邊緣扭曲，並保留補幀的額外顯示延遲。

## 本機試跑

M4 Pro，Core ML FP16，暖機後每個尺寸 3 次完整後端呼叫，包含輸入縮圖、光流推論及原解析度合成，不含 遠端顯示 超解析度、網路與顯示排程：

| 輸出尺寸 | 完整後端時間 |
| --- | --- |
| 685×418 | 11.5～12.0 ms |
| 1440×810 | 13.2～14.1 ms |
| 2880×1620 | 19.8～24.6 ms |

輸入為同一桌面截圖及右移 16 像素版本，1440／2880 為縮放測試尺寸；不是即時遠端操作測量。檢視生成畫面已無固定區塊拼接，但快速捲動、遮擋及小字仍須實機試用。低解析度光流也可能遺漏細小物件。

Core ML 超解析度先處理真實影格，完成後才交給所選補幀方式；生成幀直接呈現，不再被超解析度的非同步佇列跳過。FSR 則在補幀之後放大。Core ML 路徑使用較大尺寸合成，成本及延遲仍須實機確認。模型來源、授權與轉換詳見 internal/frameinterp/MODEL_SOURCE.md。

## 大幅移動與狀態

場景跳變判斷改為同時檢查逐像素差異及色彩直方圖差異，避免僅因大幅平移就停止補幀；這是保守的啟發式，不能保證涵蓋所有遮擋與切場。使用者拖曳視窗持續補幀。正常持續生成時提示維持目前補幀方式的狀態，不再每個工作都閃回「準備補幀」；實際逾時或回退仍顯示原因。

## 增強圖示穩定性

圖示顯示整體增強狀態：已降傳輸尺寸但視窗不需放大時保持亮燈；換幀、尺寸穩定與重新套用的短暫等待保留最近成功狀態最多 750 ms。Hover 原因即時更新。關閉、遠端拒絕或無硬體支援時立即熄滅，持續等待超過寬限時間也熄滅。

## macOS 27 啟用與回退

- 設定頁與原生推論入口共用支援判定；舊設定明確選 Apple 時，macOS 26 仍只顯示真實影格與不可用原因。自動模式在不支援 Apple 時沿用 RIFE。
- 多個顯示區域共用推論資源。Apple 工作遇到忙碌的推論鎖即回退真實影格，不排隊等待另一個視窗或尚未結束的原生處理。
- 檢查 RGBA 尺寸、stride 與實際長度，並支援最後一列不滿 stride 的子影像；建立影格或參數失敗時清除 session，下一次可重建。
- 初始化與原生推論仍在背景工作執行；逾期結果丟棄，無法保證作業系統內部呼叫可被強制中止。

先前已於 macOS 26.6.2 驗證低版本停用；macOS 27 實測結果如下。

## macOS 27 硬體 Smoke（2026-09-21）

測試環境：本機 Apple Silicon、macOS 27.0（26A428）、Xcode 27 SDK。使用合成移動物體，不擷取桌面或建立遠端連線。

- 依序以 1280×720、720×1280、640×360、1280×720 各執行 12 次，共 48 次原生 Apple 補幀；輸出尺寸及高亮物體重心均通過，重心確實位於前後輸入影格之間。
- 首次橫向初始化約 2.24 秒、首次直向約 2.44 秒、640×360 約 532 ms；返回已暖機的 720p 約 24.6 ms。初始化不可當作一般影格的即時延遲。
- 穩態中位數：橫向 720p 約 10.6 ms，直向約 7.2 ms，640×360 約 3.1 ms；返回橫向 720p 約 6.3 ms。這是短期合成工作負載，非所有機型／內容保證。
- 實際 `frameInterpolator` 排程以約 20 FPS 來源執行 5 秒：呈現 91 張真實幀與 90 張生成幀，單次排程最慢約 3.21 ms；暖機回退與關閉後恢復來源影格通過。修正回到真實幀後仍保留生成幀標記的問題。
- 尚未涵蓋真實遠端連線、視窗實際螢幕刷新、長時間效能、耗電與複雜場景畫質。

重跑硬體 Smoke（會使用本機 Apple 模型與 GPU）：

```sh
YOURDESK_APPLE_SMOKE=1 go test ./internal/frameinterp -run TestAppleHardwareSmoke -v -count=1
YOURDESK_APPLE_SMOKE=1 go test ./cmd/remote -run TestApplePresentationSmoke -v -count=1
```

### 補幀生命週期修正

停用、切換方法或重設畫面時，現在會脫離舊結果通道並清除期限及排程狀態。原生推論若較晚結束，只能回傳到啟動時捕獲的通道，不會保留在已停用的呈現器內，也不會混入新的工作階段。

macOS 27 雙視窗合成測試執行 20 秒，交替 640×360／360×640、每三秒停用半秒；生成 270 張影格，642 次停用檢查通過，最慢排程約 2.00 ms。另重跑 5 秒單視窗：90 張真實幀、89 張生成幀，最慢排程約 2.13 ms。此為短期生命週期 Smoke，不等同長時間真實連線測試。

```sh
YOURDESK_APPLE_SMOKE=1 go test -race ./cmd/remote -run 'TestAppleSwitchingSmoke|TestInterpolationResetDetachesLateResults' -v -count=1
```

上述雙視窗切換及重設測試另以 Go `-race` 通過，未回報 Go 資料競態；此工具不涵蓋 Apple 框架內部的原生執行緒。
